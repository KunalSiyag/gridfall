# Monitoring and deploy visibility

GridFall is a desktop game with no servers, so "deploys" are GitHub Releases and "monitoring" is CI plus the opt-in local logs.

| What | Where |
| --- | --- |
| CI runs (lint, gate, timing) | https://github.com/KunalSiyag/gridfall/actions |
| Nightly full gate | Actions, workflow `nightly`; a failure opens or updates an issue labelled `ci-failure` |
| Releases (deploy history) | https://github.com/KunalSiyag/gridfall/releases; each release run writes a summary with version, commit, gate result and artifact sizes |
| Code scanning (CodeQL) | https://github.com/KunalSiyag/gridfall/security/code-scanning |
| Dependency updates | https://github.com/KunalSiyag/gridfall/pulls?q=label%3Adependencies |
| API docs | GitHub Pages for this repo (`docs` workflow, generated by `tools/gen_api_docs.py`) |
| Code quality report | `quality-reports` artifact and job summary of each `ci` run: lint, complexity, duplication, dead code, coverage, tech debt |
| Build and test timing | `gate` job summary (step times against the last green `main` run) and the `gate-logs` artifact (`results.json`) |
| Local alerts | `OPS_ALERT <rule>` lines in the console, rules in `data/alert_rules.json` |
| Local errors | `user://ops/errors.jsonl` with `GRIDFALL_ERROR_LOG=1` ([error-triage.md](error-triage.md)) |
| Local analytics | `user://ops/analytics.jsonl` with `GRIDFALL_ANALYTICS=1`; `python3 tools/ops/analytics_report.py` prints events, session lengths and the session_start → enter_fp → overview_open → site_walk funnel |
