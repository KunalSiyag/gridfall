## 0. Verdict

The game is in a good running state for the short, offline, keyed-desktop path that has been exercised. Three things stand between it and a safe 30+ minute live demo:
1. The browser -> GMI keyed call has never been verified on any web build (docs say "manual"), and the client adds three non-standard headers the repo's only CORS mock does not allow.
2. Everything that grows with game days is unbounded or uncapped on the keyed path (session_cache, saved twice, autosave every game day with no interval), and the Planner (orbit) view runs a 12 s day, unsliced, on web.
3. Offline/replay play degenerates after day 12 (the replay cache ends there): identical disaster, headline and mayor posts repeat.

## 4. Offline/online boundary summary (what actually happens)

- No key / GRIDFALL_OFFLINE=1 / gmi_live flag off => live_enabled false => chat_json goes straight to _cache_lookup then the heuristic callable; live_json returns ok=false "offline" and residents use lookup() then _heuristic_plan.
- 429/5xx/408/network: retry x2 with equal-jitter backoff 0.5-4 s, Retry-After honoured (cap 8 s), within 2x timeout; counts toward the breaker; 4 in a row open it for 30 s (all roles), then one half-open probe.
- 401/403/other 4xx: not retried, not a service failure (breaker stays closed), still a "live_fail" => UI shows "down" (ratio>0.5, no min-sample).
- Timeout: HTTPRequest.timeout = per-call (mayor 70 s, support 30-45 s, residents 40-55 s); mayors' day gate gives up after 75 s (city_brain.gd:26,91-101).
- Malformed JSON / refusal: "no JSON in reply" (non-service failure), falls to cache then heuristic. HTTP 400 naming temperature: retried once at temperature 1 and remembered per model.
- Pause (tree paused) freezes in-flight HTTP polling and timeouts (GmiClient inherits the pausable process mode); the 75 s gate uses wall clock so it opens immediately after a long pause. Not a hang.
- Player key flow (web): Esc > Settings > GMI Cloud; LineEdit secret=true; set_player_key registers the key with Redact; optional localStorage store only after "Remember: On"; boot reads it back. Desktop: GMI_API_KEY, else it silently reads ~/.factory/settings.json (gmi_client.gd:176-191).

## 5. Long-running case (30+ min at 8x) - what I expect, by view

FP, keyed: 12 game days in 30 min (150 s/day). Autosave every 2.5 min, save ~3-4 MB by day 12 (2.7 MB at day 10 measured), +~110 KB/day. No growth hazards beyond session_cache; the day-13 replay cliff is not reached with a live key. FP, keyless: day 13 at ~30 min => repetition begins (R7).
Planner, keyed: day length is bounded by the slowest mayor (~10-18 s) => 100-180 days in 30 min; session_cache +~110 KB/day (both copies together) => roughly 11-20 MB per save at day 100-180 (INFERRED, extrapolated from the day 9->10 delta, not measured); unsliced ticks (R5); autosave per day (R4). This is the worst case.
Planner, keyless: days pass at 12 s / speed (0.75 s at 16x) => hundreds of days in 30 min, an autosave every 0.75-1.5 s, replay exhausted at day 13.
Hidden-tab frames: see R6.
