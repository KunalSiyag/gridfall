Lessons

Four things I would repeat

1

Write the rules and the tests first.

Agents move fast. A test gate keeps them honest.

2

Give each agent its own area.

Seven specialists shared one project without stepping on each other.

3

Write things down.

Notes and plans let us move between Droid and Claude Code when limits hit.

4

Keep a person on the deploy.

Nothing ships until someone decides.

About 1 minute. Four lessons, one sentence each. One: write the rules and the tests first. The project had a rules file for agents and one command that runs every test, and every change had to pass it. Two: give each agent its own area. In the mission each specialist owned its own files, so seven of them could work in one project at once. Three: write things down. When an agent session ends, only the documents remain, so plans, measurements and decisions went into notes the next agent could read. Four: keep a person on the deploy. Agents prepared everything, but a human decided what went live. One practical extra if there is time: usage limits ran out several times during the long mission, so save your state early.
