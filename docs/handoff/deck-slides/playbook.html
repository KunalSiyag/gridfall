The playbook the mission worked from. The slice specs and the request files date from the first-person build of 18 and 19 October (phase 2 on the growth slide); the mission kept the same rules. First, the mission map: every complaint from play is mapped to exactly one owner, and every owner has exclusive file globs. The rule at the top of the map says several agents edit the same tree at once, so respect ownership and never edit outside your area; shared files go through the orchestrator. The second rule is the one I would copy first: agents never commit. The orchestrator commits per area after the gate is green. Third, the specs. The lettered slices each had a spec with the same six parts: a goal in terms of what the player sees, the files owned exclusively, the seams consumed and provided with exact signatures, the deliverables and an acceptance test. The specs total 4,554 lines in 12 files. When a slice needed something outside its files it wrote a request file instead of editing: there are 14 of them. Last, the gate: quick before every commit, full before every hand-off, and heavy runs take a machine-wide lock so several agents do not overload the box.
