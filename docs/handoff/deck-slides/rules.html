AGENTS.md
has its own linter:

a path or command it names that no longer exists fails the check, so the agents’ instructions cannot drift from the repo.

This is the slide for people who ask how you let agents write 158k lines and still trust it. Three mechanisms, each enforced by a script rather than by good intentions. One: baselines. Legacy findings are recorded (102 functions over the complexity limit, 82 duplicate clusters and so on) and only new findings fail, so the agent is never asked to clean the world, only to not make it worse. Two: boundaries.json says which layers may import which; the sim and AI layers may not import world, ui or fp, and each fp feature folder may not reach into another one (five documented exceptions). Three: the gate. Each Godot step runs with a fresh user directory, offline, with the GMI key unset and a timeout; a step that dies without a verdict is retried once. A real lesson: Godot prints ERROR lines without failing a run, which hid real bugs (issues 67 and 72), so engine_errors.py now fails any such line that is not on an allow-list of 13 patterns, each with a written reason. Last line on the slide: agents_md.py validates AGENTS.md, so the briefing the agents read has a linter.
